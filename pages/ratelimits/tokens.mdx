## Tokens

---

The current ratelimits are enforced as such:
- If a route is not listed here it effectively uses the `global` ratelimit.
- `/canvas` endpoints follow the same tiered limits as everything else, see the `/canvas` row in each table below. Canvas requests are counted separately, they don't use up your `/` or `/lyrics` limit and vice versa.
- A token that is invalid, expired, banned or a [legacy token](/ratelimits/legacytokens) is rejected with a `403`. It is not treated as an unauthenticated request. See [Token errors](#token-errors).

### Handling our ratelimits

To avoid getting ratelimited there are multiple ways to handle this

- You can check one of the following headers:
  - `x-ratelimit-limit` => Tells you your limit for the timeframe
  - `x-ratelimit-remaining` => Tells you how many requests are left within with your bucket
  - `x-ratelimit-next-available` => Tells you when your oldest request expires

If you get ratelimited you'll get a `429` with the following message:
```json
  {
    "retryAfter": "2025-05-06T22:41:57.406Z",
    "retryAfterMs": 60000,
    "error": "You have been ratelimited.",
    "note": "You can generate a token for free at https://some-random-api.com/user/settings and increase your limits."
  }
```

The `note` tells you how to get higher limits and depends on how you made the request:

      </td>
    </tr>
    <tr>
      <td>Banned token</td>
      <td>
        <Code>This token has been banned.</Code> The response can also include a <Code>reason</Code> and a <Code>bannedAt</Code> date.

    </tr>

[Legacy tokens](/ratelimits/legacytokens) get the same response as any other invalid token.
